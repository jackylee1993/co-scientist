# 评审量表与判官校准

这份量表服务于两个目的：让不同 agent 的评分可比，让“为什么这个假设排第一”可以被复查。它不是客观真值，只是**结构化判断**。

## 0. 对齐门槛（Alignment gate，先于评分）

在打分前先问三个问题。任何一项为“否”，先 `revise` 或 `reject`，不要用高分掩盖跑题：

1. 这个假设是否直接回答 `goal.question`，而不是回答一个相邻但不同的问题？
2. 是否遵守 `constraints`（时间、人员、数据、平台、合规）？如果做不完，是否明确写了 blocker？
3. 是否违反 `non_goals`、`safety` 或数据边界？

对齐不是“越接近主流越好”；一个挑战主流但仍在目标范围内的假设，可以通过。跑题、超范围、资源不可能，才是不对齐。

## 1. 七个维度（1–10）

### Correctness（正确性 / 机制自洽）

| 分数 | 含义 |
|---:|---|
| 1 | 与已知机制/物理/化学/生物学冲突，或内部自相矛盾 |
| 3 | 机制链条有明显断裂，关键环节靠猜测 |
| 5 | 机制合理，但承重假设未验证；无直接反证 |
| 7 | 多条间接证据支持；关键环节有文献依据 |
| 9 | 直接实验/观测支持核心机制；替代解释已被排除 |
| 10 | 已被独立重复验证（极少给） |

### Novelty（新颖性）

| 分数 | 含义 |
|---:|---|
| 1 | 与已有工作完全相同，或只是换词 |
| 3 | 微调参数/体系/指标，增量很小 |
| 5 | 新组合、新体系、新尺度，但机制不新 |
| 7 | 新机制、新因果链，或对老问题的新解释 |
| 9 | 推翻/显著修正主流解释，或开辟新问题 |
| 10 | 领域范式级（几乎不给） |

必须写 `closest_prior_work`。找不到就先降置信度，不要直接给高分。

### Testability（可检验性）

| 分数 | 含义 |
|---:|---|
| 1 | 无法证伪；任何结果都能解释 |
| 3 | 需要不可得的数据/平台，或只能做相关性 |
| 5 | 可在约束内做，但实验不能区分主要替代解释 |
| 7 | 2–4 周可得到清晰的支持/反证 |
| 9 | 一个便宜、干净的实验就能判决 |
| 10 | 已有现成数据可直接检验（极少） |

### Impact（影响）

| 分数 | 含义 |
|---:|---|
| 1 | 只影响一个边角案例 |
| 3 | 对一个小同行群体有参考价值 |
| 5 | 改变一个子领域的认识或一个局部的管理做法 |
| 7 | 改变主流模型/指南/实践 |
| 9 | 跨子领域影响 |
| 10 | 教科书级（几乎不给） |

### Feasibility（可行性）

| 分数 | 含义 |
|---:|---|
| 1 | 资源/时间差一个数量级以上 |
| 3 | 关键平台或数据不可得 |
| 5 | 勉强可做，但会挤压其他工作 |
| 7 | 现有人员/平台可在计划内完成 |
| 9 | 本周就能开始，风险可控 |
| 10 | 几乎零额外成本 |

### Grounding（证据支撑）

| 分数 | 含义 |
|---:|---|
| 1 | 关键主张没有任何来源 |
| 3 | 只有类比/间接证据 |
| 5 | 有相关文献，但不是直接支持 |
| 7 | 多条原始研究支持关键环节 |
| 9 | 直接数据/实验支持 |
| 10 | 多体系重复验证 |

### Safety / Ethics（安全与伦理）

| 分数 | 含义 |
|---:|---|
| 1 | 明确不可接受（伤害、规避监管、双重用途滥用） |
| 3 | 高风险，需要严格审批且可能不应做 |
| 5 | 需要伦理/生物安全/数据合规审查 |
| 7 | 低风险，按常规合规执行 |
| 9 | 无明显额外风险 |
| 10 | 无额外风险且有益于合规实践 |

## 2. 加权总分与裁决

加权总分：

```text
total = Σ(weight_i × score_i)
```

默认权重来自 `goal.json`；常见默认：

- novelty 0.25
- correctness 0.25
- testability 0.20
- impact 0.20
- feasibility 0.10

`grounding` 和 `safety` 可以作为**门槛**而不是加权项：

- `safety < 5` → 直接 `reject` 或转人工，不进入排序。
- `grounding < 3` → 最高只能 `revise`，不能 `pass`。
- `correctness < 4` 且有致命缺陷 → `reject`。

裁决建议（不是硬规则，允许判官根据致命缺陷覆盖）：

| 条件 | verdict |
|---|---|
| 有致命缺陷且不可修复 | `reject` |
| 核心可辩护，但需补证据/缩小范围 | `revise` |
| 可进入锦标赛，无致命缺陷 | `pass` |
| 信息不足，无法判断 | `abstain` |

## 3. 评审类型与深度

| 类型 | 是否检索 | 主要目的 | 典型耗时 |
|---|---|---|---|
| triage | 否 | 快速筛掉明显坏假设 | 1–2 分钟 |
| full | 是 | 正确性 + 新颖性 + 可检验性 | 5–10 分钟 |
| deep | 是 | 承重假设逐条验证 | 10–20 分钟 |
| observation | 是 | 能否更好解释 long-tail 观测 | 5–10 分钟 |
| simulation | 可选 | 逐步模拟机制/实验，找失败模式 | 5–10 分钟 |
| redteam | 是 | 替代解释、混杂、外推、伦理 | 5–10 分钟 |
| human | 否 | 把专家意见结构化 | 依输入 |

## 4. 两两比较协议（Debate）

1. **顺序盲读**：先按展示顺序称呼“第一位/第二位”，避免 ID/排名锚定。
2. **Steelman**：分别写出最强版本，补全未明说的合理机制。
3. **决定性问题**：从目标权重中选 2–3 个能分开两者的问题。
4. **三回合辩论**：开场 → 交叉质询 → 收束（各自承认一个无法回避的弱点）。
5. **逐项评分**：按同一量表打分；不要先给总分再倒推单项。
6. **裁决**：winner / draw；写 `decisive_criterion`。
7. **偏差自检**：交换顺序是否改变判断？篇幅/语气是否影响？是否引入新事实？

## 5. 判官偏差与控制

| 偏差 | 表现 | 控制 |
|---|---|---|
| 位置偏差 | 先展示者胜率显著 > 50% | 随机化 `order_presented`；关键比赛交换顺序复赛；统计 `position_bias` |
| 篇幅偏差 | 更长/术语更多的假设更容易赢 | 比较胜者/败者平均长度；提示判官“长度不加分”；必要时截断到同等长度 |
| 锚定偏差 | 被当前 Elo 排名影响 | 判官只看卡片与评审，不看排行榜；或把排行榜放在最后并明确“仅背景” |
| 从众/共识幻觉 | 多个评审给相似分数，但都没查证据 | 至少一个 `deep` 或 `redteam` 评审；要求引用具体来源 |
| 自偏好 | 同一模型偏爱自己风格的输出 | 多判官/多 persona；交换顺序；人工抽检 |
| 新颖性通胀 | 把“没查到”当成“新” | 必须写 `closest_prior_work`；找不到就降置信度 |
| 可行性忽视 | 科学上漂亮但做不完 | feasibility 作为硬约束；资源不足直接降分 |
| 安全盲区 | 只评科学价值，不评伦理/两用 | 单独 `safety` 门槛；高风险转人工 |

## 6. 校准流程

### 6.1 初始校准

1. 找 5–10 个**已知质量**的历史假设/论文摘要（例如：已被验证、已被推翻、明显复刻）。
2. 让判官在不知道标签的情况下评分。
3. 计算：
   - 与人类评分的 Spearman 相关；
   - 高/低质量组的分数差（区分度）；
   - 位置偏差（交换顺序后的胜率变化）。
4. 如果区分度低：增加评分锚点示例；如果位置偏差高：强制交换顺序；如果普遍偏高：要求使用全量程并给反例。

### 6.2 运行中校准

- 每 20 场比赛，抽 2 场做“交换顺序复赛”；如果结果翻转，标记该比赛为低置信度。
- 统计 `position_bias` 和 `verbosity_bias`；显著时在下一轮提示词中加入对应警告。
- 对 top-5 假设做一次独立 `redteam` 评审；如果 redteam 与 full 结论冲突，进入人工复核。

### 6.3 运行后校准

- 如果有外部结果（实验、专家评分、后续验证），计算：
  - top-1/top-3 命中率；
  - Elo 与外部评分的相关性；
  - 评审分数与外部结果的相关性。
- 把结果写入 `meta/outcomes.json`（`supported` / `refuted` / `inconclusive`；格式见 `assets/outcomes.example.json`），供 `rsi update` 和 `rsi compare` 使用；自由文本说明可另写 `meta/outcomes.md`。
- 如果 Elo 与外部结果长期不相关，降低 Elo 在最终决策中的权重，改用评审分数/专家判断。

## 7. 评分记录的最低要求

每条评审至少包含：

- `hypothesis_id`
- `review_type`
- `verdict`
- 七个维度的分数（缺失维度写 `null`，不要默认 5）
- 至少 1 条具体优点和 1 条具体缺点
- `fatal_flaws`（没有就空数组）
- `novelty_check.closest_work`
- `confidence`
- 引用到的来源（作者/年/DOI）

没有这些字段的评审，不应进入汇总。
